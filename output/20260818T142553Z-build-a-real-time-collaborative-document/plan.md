## Implementation

### Phase 1 — Project initialization

- Initialize a git repository and create a `pyproject.toml`.
- Add core dependencies: `fastapi`, `uvicorn`, `redis`[^redis-1], `sqlmodel`[^sqlmodel-1], `alembic`[^alembic-1], `pyjwt`[^pyjwt-1], `casbin`[^casbin-1], `text-ot`[^text-ot-1].
- Install `sqlmodel` with `uv add sqlmodel` and the rest with `pip install`.
- Create directory layout: `app/`, `app/models/`, `app/api/`, `app/ws/`, `app/auth/`, `alembic/`.
- Commit initial structure.

### Phase 2 — Database schema and migrations

- Define a `Document` model using `SQLModel` with fields `id`, `title`, `content`, `updated_at`[^sqlmodel-1].
- Create a SQLAlchemy engine via `create_engine("sqlite:///db.sqlite")`[^sqlmodel-1].
- Run `alembic init alembic` to generate migration environment[^alembic-1].
- Add a revision with `alembic revision --autogenerate -m "create documents table"` and ensure it creates the `documents` table.
- Apply migrations with `alembic upgrade head`.
- Verify the table exists by opening a session and querying.

### Phase 3 — JWT authentication layer

- Implement `generate_token(user_id: str) -> str` using `jwt.encode`[^pyjwt-1].
- Implement `decode_token(token: str) -> dict` using `jwt.decode`[^pyjwt-1].
- Create a FastAPI dependency `get_current_user` that reads the `Authorization` header, decodes the token, and raises `HTTPException(401)` on failure.
- Add a `/login` endpoint that validates a dummy username/password and returns a JWT.
- Protect all subsequent routes with `Depends(get_current_user)`.

### Phase 4 — Casbin access control integration

- Place `model.conf` and `policy.csv` files in `app/auth/`.
- Instantiate a Casbin `Enforcer` with those files at startup[^casbin-1].
- Write a dependency `enforce_document_access(user: str, doc_id: int, action: str)` that calls `enforcer.enforce(user, "document", str(doc_id), action)` and raises `403` if denied.
- Apply this dependency to document‑related endpoints (read, write, delete).

### Phase 5 — WebSocket endpoint and operational transform

- Create a FastAPI WebSocket route at `/ws/{doc_id}`.
- On connection, load the latest document snapshot from the DB and send it to the client.
- Subscribe to a Redis channel named `doc:{doc_id}` using Redis pub/sub[^redis-1] and forward any incoming patches to the client.
- When a client sends a patch, apply it with the `text-ot` library (API details not covered in the brief – further research required)[^text-ot-1].
- After applying, update the document snapshot in the DB and publish the patch to the same Redis channel.
- Handle disconnects by unsubscribing and closing the Redis connection.

### Phase 6 — Reconnection handling and missed‑update replay

- Require clients to send the last known version number when (re)connecting.
- Query the DB for all patches with a version greater than the provided one and send them sequentially.
- Ensure the Redis subscriber is re‑established after reconnection.
- Add FastAPI shutdown event to gracefully close Redis connections.
- Write integration tests that simulate disconnects and verify missed patches are replayed correctly.

## Pitfalls

- text-ot library API is not described in the brief; you must consult its documentation before implementing transform logic.
- Hard‑coding the JWT secret is insecure; store it in environment variables or a secret manager.
- Casbin policy files must be kept in sync with application logic; mismatches cause authorization failures.
- Redis pub/sub does not guarantee message delivery to late subscribers; consider buffering or persisting patches.
- SQLModel models and Alembic migrations can diverge; always regenerate migrations after model changes.
- WebSocket connections need proper cleanup to avoid leaking Redis subscriptions or DB sessions.
