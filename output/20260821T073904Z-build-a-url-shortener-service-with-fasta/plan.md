    return {"item_id": item_id, "q": q}

## Implementation

### Phase 1 — Project Setup

1. Initialize a new project directory and run `uv init`.
2. Add FastAPI with standard extras: `uv add "fastapi[standard]"`[^fastapi-1].
3. Add Uvicorn: `pip install uvicorn`[^uvicorn-1].
4. Add Redis client library: `pip install redis`[^redis-1].
5. Add SQLAlchemy: `pip install sqlalchemy`[^sqlalchemy-1].
6. Create a `requirements.txt` via `uv pip freeze > requirements.txt`.

### Phase 2 — Core Application Skeleton

1. Create `app/main.py` and instantiate `app = FastAPI()`[^fastapi-1].
2. Add a health check route `GET /health` returning `{"status":"ok"}`.
3. Add `if __name__ == "__main__": uvicorn.run("app.main:app", port=8000, log_level="info")`[^uvicorn-1].
4. Create a `app/config.py` with Redis connection URL and SQLAlchemy DB URL.
5. Initialize a Redis client in `app/redis_client.py` using `redis.from_url`[^redis-1].
6. Initialize SQLAlchemy engine and sessionmaker in `app/db.py`.

### Phase 3 — Data Modeling with SQLAlchemy

1. Define a `Base` declarative class in `app/models.py`.
2. Create `Url` model with columns: `id` (PK, int), `original_url` (String), `short_code` (String, unique), `created_at` (DateTime), `clicks` (Integer, default 0) using SQLAlchemy ORM[^sqlalchemy-1].
3. Create `Click` model to store individual click timestamps if detailed analytics are needed.
4. Generate tables via `Base.metadata.create_all(engine)`.
5. Add a utility function `generate_short_code()` that returns a 6‑character base62 string.
6. Export a `get_db()` dependency that yields a SQLAlchemy session.

### Phase 4 — Redis Caching Layer

1. In `app/redis_cache.py`, write `get_short_url(code)` that attempts `redis_client.get(code)`[^redis-1].
2. Write `set_short_url(code, url, ttl=None)` to store the mapping with optional TTL[^redis-1].
3. On URL creation, after persisting to DB, cache the `short_code -> original_url` pair.
4. On redirect, first check Redis; if miss, query DB, then cache the result.
5. Use Redis atomic `INCR` to increment click count if using a simple counter[^redis-1].
6. Ensure Redis connection errors are caught and fallback to DB lookup.

### Phase 5 — Rate Limiting with Redis

1. Create `app/rate_limit.py` and define `RATE_LIMIT = 10` and `WINDOW_SECONDS = 60` constants[^fastapi-1].
2. Implement `def is_allowed(ip: str) -> bool:` that calls `redis_client.incr(f"rl:{ip}")` and if the result is 1 sets expiry with `redis_client.expire(f"rl:{ip}", WINDOW_SECONDS)`[^redis-1].
3. Return `True` when the incremented count is <= `RATE_LIMIT`, otherwise `False`.
4. In `app/main.py` import `is_allowed` and in the `POST /shorten` handler retrieve the client IP (e.g., `request.client.host`) and raise `HTTPException(status_code=429, detail="Rate limit exceeded")` if `is_allowed` returns `False`[^fastapi-1].
5. Wrap Redis calls in try/except to fallback to allowing the request if Redis is unavailable[^redis-1].

### Phase 6 — API Endpoints and Analytics

1. `POST /shorten` accepts JSON `{ "url": "..." }`, generates a short code, stores in DB, caches in Redis, and returns `{ "short_url": "http://host/{code}" }`.
2. `GET /{code}` looks up the original URL via Redis cache, falls back to DB, increments click count, and redirects (HTTP 307) to the original URL.
3. `GET /analytics/{code}` returns JSON with total clicks and optional list of recent click timestamps from the `Click` table.
4. Use FastAPI dependencies to inject DB session and Redis client.
5. Mark route functions as `async def` where I/O is awaited (e.g., Redis calls) per FastAPI GOTCHA[^fastapi-1].
6. Add Pydantic schemas for request and response models.

### Phase 7 — Running and Verification

1. Start the service with `uv run fastapi dev`[^fastapi-1] for auto‑reload.
2. Verify health endpoint returns 200.
3. Use `curl` to create a short URL and ensure the response contains a valid short link.
4. Access the short link and confirm it redirects correctly and click count increments.
5. Call `/analytics/{code}` and check the click count matches accesses.
6. Run a simple load test (e.g., `hey`) to ensure Redis cache reduces DB hits.

## Pitfalls

- Missing quotes around `fastapi[standard]` in `uv add` will cause install failures[^fastapi-1].
- Defining route handlers with `def` instead of `async def` when awaiting Redis will block the event loop[^fastapi-1].
- Using the deprecated `uvicorn.workers.UvicornWorker` with Gunicorn can break future deployments[^uvicorn-1].
- Storing large click logs in Redis without TTL may exhaust memory; keep only aggregate counters in Redis and persist detailed logs in the DB.
- Generating short codes without collision handling can lead to duplicate keys; always check DB uniqueness before committing.
- If Redis is unavailable, ensure the app gracefully falls back to DB queries to avoid total outage.
