## Implementation

### Phase 1 — Initialize project and dependencies

- Create project root directory and `pyproject.toml` using `uv init`.
- Run `uv add "fastapi[standard]"` to install FastAPI with its standard extras[^fastapi-1].
- Install Uvicorn with `pip install uvicorn`[^uvicorn-1].
- Initialize a git repository and add a `.gitignore` for `__pycache__` and `.venv`.
- Create a `requirements.txt` by exporting the lockfile (`uv pip freeze > requirements.txt`).
- Commit initial setup.

### Phase 2 — Create FastAPI application entrypoint

- Add `app/main.py`.
- Import `FastAPI` and instantiate `app = FastAPI()`[^fastapi-1].
- Define a simple health‑check route using `@app.get("/health")` that returns `{"status":"ok"}`[^fastapi-1].
- Ensure the file defines `__all__ = ["app"]` for import clarity.
- Add a module‑level docstring describing the service.
- Run `uv run fastapi dev` to verify the server starts[^fastapi-1].

### Phase 3 — Define Pydantic models

- In `app/schemas.py` import `BaseModel` from `pydantic`.
- Create a `User` model with fields `name: str` and `age: int` as shown in the docs[^pydantic-1].
- Add a `UserCreate` model inheriting from `User` if needed for future extensions.
- Export the models via `__all__`.
- Write type‑annotated docstrings for each model.
- Run a quick import test to ensure models compile.

### Phase 4 — Implement CRUD endpoints

- In `app/main.py` import the `User` model.
- Add an async `@app.post("/users")` endpoint that accepts a `User` body and returns it with a generated `id`.
- Add an async `@app.get("/users/{user_id}")` endpoint returning a placeholder user.
- Use `async def` for all handlers as recommended for async support[^fastapi-1].
- Store users in an in‑memory dict for simplicity.
- Add proper response models using `response_model=User`.
- Test endpoints with `curl` or HTTPie.

### Phase 5 — Add production run script

- Create `run.py` at project root.
- Import `uvicorn` and the `app` instance.
- Call `uvicorn.run("app.main:app", host="0.0.0.0", port=8000, log_level="info")` as documented[^uvicorn-1].
- Guard the call with `if __name__ == "__main__":`.
- Document usage in `README.md`.
- Ensure the script works by executing `python run.py`.

### Phase 6 — Verify functionality and cleanup

- Start the dev server with `uv run fastapi dev` and access `http://127.0.0.1:8000/health`.
- Use `curl -X POST -H "Content-Type: application/json" -d '{"name":"Alice","age":30}' http://127.0.0.1:8000/users` to test creation.
- Retrieve the created user via `GET /users/{id}`.
- Run the production script `python run.py` and repeat the checks.
- Add basic unit tests in `tests/test_api.py` using `httpx` (optional, not required by briefs).
- Commit all changes and tag a release version.

## Pitfalls

- Quote `fastapi[standard]` when using `uv add` to avoid shell parsing issues[^fastapi-1].
- Define endpoints with `async def` if using async features; otherwise FastAPI will warn[^fastapi-1].
- `fastapi dev` enables auto‑reload for development; switch to `fastapi run` or a custom `uvicorn.run` script for production[^fastapi-1].
- The `uvicorn.workers.UvicornWorker` module is deprecated; do not use it for deployment[^uvicorn-1].
- Ensure Uvicorn is installed via pip, not via `uv add`, as the brief only lists a pip install command[^uvicorn-1].
- Running the server without specifying the correct import path (e.g., `app.main:app`) will cause import errors.
