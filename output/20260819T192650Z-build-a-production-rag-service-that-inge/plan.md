## Implementation

### Phase 1 — Error handling and retries

- Wrap PDF reading with `PdfReader` in a try/except block and log extraction failures.
- Validate uploaded files using Pydantic models and catch `ValidationError` to return clear HTTP 422 responses.
- Implement a FastAPI exception handler that captures generic exceptions and returns a 500 error with a sanitized message.
- Add retry logic with a configurable max_attempts for Weaviate batch imports, breaking after successful import or exceeding attempts.
- Use exponential backoff between retries when contacting the Weaviate client.
- Log all errors with contextual information (file name, page number, operation) using the standard `logging` module.

## Pitfalls

- FastAPI production should be run with `fastapi run` rather than the development command `uv run fastapi dev`[^fastapi-1]
- Weaviate client requires an open gRPC port (default 50051) on the server for connectivity[^weaviate-client-1]
- pypdf 3.1.0 introduced significant changes; consult the migration guide when upgrading[^pypdf-1]
- The package name changed to `python_multipart`; using the old `import multipart` may emit warnings unless the legacy package is also installed[^python-multipart-1]
- Pydantic raises `ValidationError` for request validation failures and must be caught to return proper HTTP errors[^pydantic-1]
- Sentence‑Transformers needs PyTorch 2.2+ and transformers v5.0+; mismatched versions cause import errors[^sentence-transformers-1]
