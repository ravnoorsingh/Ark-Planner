# Implementation plan

> **Goal:** Build a CLI tool that converts markdown files to styled PDFs with a table of contents. Use markdown for the markdown parser. Use weasyprint for the pdf generator. Use click for the cli framework.

The plan creates a Click‑based command‑line interface that reads a Markdown file, converts it to HTML with the markdown library, and renders a styled PDF using WeasyPrint. It also adds a generated table of contents and verifies the output.

## Library reference

### markdown [^markdown-1]

*The Markdown Guide* is a free and open-source reference guide that explains how to use Markdown, the simple and easy-to-use markup language you can use to format virtually any document. Markdown makes writing on the web fast and easy.

### weasyprint [^weasyprint-1]

WeasyPrint is a smart solution that helps web developers create PDF documents. It converts simple HTML pages into high‑quality PDFs with features like tables of contents, customized headers, and advanced typography.

## Implementation

### Phase 1 — Project setup and dependencies

- Create project root directory and run `git init`.
- Set up a Python virtual environment (`python -m venv .venv`).
- Activate the venv and install required packages: `pip install markdown weasyprint click`.
- Freeze exact versions to `requirements.txt`.
- Create an entry‑point script `cli.py` with a shebang (`#!/usr/bin/env python`).
- Add a `.gitignore` that excludes the virtual environment and compiled files.

### Phase 2 — CLI skeleton with Click

- Import `click` in `cli.py` and define a `@click.command()` function named `convert`.
- Add `@click.argument('input_path', type=click.Path(exists=True, dir_okay=False))`.
- Add `@click.argument('output_path', type=click.Path())`.
- Add optional `--style` option to accept a CSS file path.
- Provide helpful `--help` strings for each argument/option.
- Inside the command, call a helper `process_file(input_path, output_path, style_path)`.

### Phase 3 — Markdown to HTML conversion

- Import `markdown` from the markdown package[^markdown-1].
- Read the contents of `input_path` into a string.
- Convert the markdown string to HTML with `markdown.markdown(text, extensions=['extra','toc'])`.
- If a CSS file is supplied, embed a `<link rel="stylesheet" href="{style_path}">` tag in the HTML `<head>`.
- Insert a `<nav class="toc"></nav>` placeholder after the opening `<body>` to let WeasyPrint generate a TOC.
- Return the final HTML string.

### Phase 4 — PDF generation with WeasyPrint

- Import `HTML` and `CSS` from `weasyprint`[^weasyprint-1].
- Create a `HTML(string=html_content)` object.
- If a CSS path was provided, load it via `CSS(filename=style_path)` and pass it as a stylesheet.
- Call `HTML.write_pdf(output_path, stylesheets=[css])` to produce the PDF; the `<nav class="toc">` element triggers automatic TOC creation.
- Ensure the PDF is written atomically and close any resources.

### Phase 5 — Integrate conversion steps and error handling

- Implement `process_file` to orchestrate markdown conversion then PDF rendering.
- Wrap file I/O in `try/except` blocks and emit clear `click.ClickException` messages on failure.
- Validate that the output directory exists or create it.
- Return exit code 0 on success.
- Add a `if __name__ == '__main__':` guard to invoke the Click CLI.

### Phase 6 — Verification and testing

- Write a sample `sample.md` containing multiple headings to test TOC generation.
- Run the CLI: `python cli.py sample.md sample.pdf --style style.css`.
- Open `sample.pdf` to confirm styled content and a functional table of contents.
- Test error paths: missing input file, invalid CSS path, and permission errors.
- Optionally add a basic unit test using `pytest` that checks the PDF file size > 0.

## Pitfalls

- WeasyPrint depends on external libraries (Cairo, Pango, GDK) that must be installed on the host system before the Python package works
- The markdown library’s `toc` extension only generates a placeholder; the actual TOC layout relies on CSS rules that must be provided
- Click will not auto‑create missing directories; the script must ensure the output path’s parent exists
- Embedding a CSS file via a relative `<link>` works only if the path is accessible to WeasyPrint; use absolute paths or `CSS(filename=…)`
- Temporary HTML strings are kept in memory; very large documents may require streaming to avoid high RAM usage
- Failure to activate the virtual environment can lead to importing system‑wide packages with incompatible versions
