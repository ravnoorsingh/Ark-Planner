## Implementation

### Phase 1 — Project initialization and dependencies

- Run `uv init` to create a new project.
- Add FastAPI with standard extras: `uv add "fastapi[standard]"`[^fastapi-1].
- Add httpx: `uv add httpx`[^httpx-1].
- Add pydantic: `uv add pydantic`[^pydantic-1].
- Add uvicorn: `uv add uvicorn`[^uvicorn-1].
- Add the MCP SDK (assumed pip package name `mcp`): `uv add mcp`[^mcp-1].

### Phase 2 — Define Pydantic schemas for tool I/O

- Create `schemas.py`.
- Define `SearchRequest(BaseModel)` with fields `query: str` and optional `limit: int`.
- Define `SearchResult(BaseModel)` with fields `page_id: str`, `title: str`, `snippet: str`.
- Define `PageRequest(BaseModel)` with field `page_id: str`.
- Define `PageResponse(BaseModel)` with fields `page_id: str`, `title: str`, `content: str`.
- Define `ToolListResponse(BaseModel)` with field `tools: List[str]`.

### Phase 3 — Implement FastAPI routes using httpx

- Create `app/main.py` and instantiate `app = FastAPI()`[^fastapi-1].
- Add async dependency `httpx.AsyncClient()` for outbound wiki calls.
- Implement `@app.get("/tools") async def list_tools() -> ToolListResponse` returning static tool names.
- Implement `@app.post("/search") async def search(req: SearchRequest) -> List[SearchResult]` that calls `GET /api/search` on the wiki via httpx with bearer token header.
- Implement `@app.post("/page") async def fetch_page(req: PageRequest) -> PageResponse` that calls `GET /api/pages/{id}` via httpx.
- Use `await client.get(...)` to respect async flow[^httpx-1].

### Phase 4 — Add bearer‑token authentication middleware

- Create `auth.py` with a FastAPI dependency that extracts `Authorization` header and validates the token (placeholder logic).
- Apply the dependency to the `/search` and `/page` routes using `Depends`.
- Return 401 response if token is missing or invalid.
- Document the expected token format in the OpenAPI schema.

### Phase 5 — Integrate MCP SDK and register tools

- In `app/mcp_integration.py` import the MCP SDK (`import mcp`).
- Note: The official MCP Python SDK documentation does not specify exact registration APIs, so insert a placeholder `mcp.register_tool(...)` call for each tool definition[^mcp-1].
- Configure the MCP server to use a streamable HTTP transport (placeholder `mcp.StreamableTransport()`).
- Ensure the MCP registration runs at startup by adding a FastAPI `@app.on_event("startup")` handler.

### Phase 6 — Run and verify the service

- Add `if __name__ == "__main__": uvicorn.run("app.main:app", port=8000, log_level="info")`[^uvicorn-1].
- Start the server with `uv run fastapi dev` for development or `uv run python -m app.main` for production.
- Use httpx or curl to call `/tools`, `/search`, and `/page` and confirm JSON responses match the Pydantic models.
- Verify that requests without a valid bearer token receive 401.
- Log successful startup with `logfire.info("MCP Wiki server started")`[^pydantic-1].

## Pitfalls

- MCP SDK registration APIs are not detailed in the brief; placeholder code must be replaced with real calls.
- httpx requires Python 3.9+; ensure the runtime meets this requirement[^httpx-1].
- Async FastAPI routes must use `async def`; using sync functions will block the event loop[^fastapi-1].
- Bearer‑token validation logic is security‑critical; a simple placeholder is insufficient for production.
- uvicorn's `uvicorn.workers` module is deprecated; avoid using it for deployment[^uvicorn-1].
- Missing `fastapi[standard]` quotes during installation can cause install failures[^fastapi-1].
