## Library reference

### fastapi [^fastapi-1] [^fastapi-2]

FastAPI is a modern, high‑performance web framework for building APIs with Python, using standard Python type hints. It automatically reads request bodies as JSON, validates them with Pydantic models, and generates OpenAPI documentation with JSON Schema definitions.

**`FastAPI()`**

```
from fastapi import FastAPI

app = FastAPI()
```

**`app.post("/items/")`**

```
@app.post("/items/")
async def create_item(item: Item):
    return item
```

**`BaseModel`**

```
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
```

**`uv run fastapi dev`**

```
uv run fastapi dev
```

### pydantic [^pydantic-1] [^pydantic-2]

Pydantic is the most widely used data validation library for Python. Fast and extensible, Pydantic plays nicely with your linters/IDE/brain. Define how data should be in pure, canonical Python 3.10+, validate it with Pydantic.

**`BaseModel`**

Base class for creating data models with validation.

```
class User(BaseModel):
    name: str

    age: int
```

**`ValidationError`**

Exception raised when validation fails.

```
from pydantic import ValidationError

try:
    User(**external_data)
except ValidationError as e:
    print(e)
```

**`PositiveInt`**

Type hint for positive integers.

```
from pydantic import PositiveInt

tastes: dict[str, PositiveInt]
```

**`model_dump`**

Return a dict representation of the model.

```
print(user.model_dump())

  'tastes': {'wine': 9, 'cheese': 7, 'cabbage': 1},
}
"""
```

**`Agent`**

Core class for building production agents in Pydantic AI.

```
model = 'openai:gpt-5.6-sol'

agent.run_sync('Does it snow?')
```

### uvicorn [^uvicorn-1] [^uvicorn-2]

Uvicorn is an ASGI web server implementation for Python. It supports HTTP/1.1 and WebSockets.

**`uvicorn.run`**

```
import uvicorn

async def app(scope, receive, send):
    ...

if __name__ == "__main__":
    uvicorn.run("main:app", port=5000, log_level="info")
```

## Implementation

### Phase 1 — Initialize project and dependencies

- Create a project directory and navigate into it.
- Add FastAPI with standard extras using `uv add "fastapi[standard]"`[^fastapi-1].
- Add Uvicorn server using `uv add uvicorn`[^uvicorn-1].
- Create an empty `requirements.txt` (optional for documentation).

### Phase 2 — Define request models

- Create `models.py`.
- Import `BaseModel` from Pydantic[^pydantic-1].
- Define an `Item` class inheriting from `BaseModel` with fields `name: str`, `description: str | None = None`, `price: float`, `tax: float | None = None`.
- Ensure the file is importable from other modules.

### Phase 3 — Build FastAPI application and routes

- Create `main.py`.
- Import `FastAPI` from `fastapi` and instantiate `app = FastAPI()`[^fastapi-2].
- Import the `Item` model from `models.py`.
- Add a POST endpoint `@app.post("/items/")` that receives `item: Item` and returns the model instance.
- (Optional) Add a simple health‑check GET endpoint `@app.get("/health")` returning `{"status":"ok"}`.

### Phase 4 — Configure Uvicorn entry point

- In `main.py`, add the standard guard:
```python
if __name__ == "__main__":
    import uvicorn
    uvicorn.run("main:app", port=8000, log_level="info")
```
- This uses `uvicorn.run`[^uvicorn-2] to start the ASGI server.
- No additional configuration files are required for this minimal setup.

### Phase 5 — Run development server

- Start the app with FastAPI's development command `uv run fastapi dev`[^fastapi-2].
- Verify that the OpenAPI docs are reachable at `http://127.0.0.1:8000/docs`.
- The dev server provides auto‑reload; ensure `watchfiles` is available via the standard extras.

### Phase 6 — Test the POST endpoint

- Use `curl` or `http` to POST a JSON payload to `http://127.0.0.1:8000/items/` matching the `Item` schema.
- Confirm the response echoes the submitted data and that validation errors are returned for malformed payloads.
- Document the example request and response in a `README.md`.

### Phase 7 — Type checking with mypy

- Verify that all functions and models have proper type annotations according to PEP 484[^typing-1].
- Run a PEP 484‑compliant static type checker (e.g., mypy) on the project source files.
- Fix any type errors reported before proceeding.

## Pitfalls

- GET requests with bodies are discouraged and not documented in Swagger UI[^fastapi-2].
- For production, run the app with `fastapi run` instead of the dev command[^fastapi-2].
- `uvicorn.workers.UvicornWorker` is deprecated and will be removed[^uvicorn-2].
- `--reload` cannot be combined with `--workers` in Uvicorn CLI[^uvicorn-2].
- Auto‑reload requires the `watchfiles` package; ensure `fastapi[standard]` is installed[^uvicorn-2].
- Pydantic requires Python 3.10+; using an older interpreter will cause import errors[^pydantic-2].
